# Firmware

Dukungan pembacaan adalah Linux amd64 dan arm64 dengan `fwupdmgr`. Inventaris menggunakan `get-devices --json`, sedangkan daftar kandidat memakai `get-updates --json` dan metadata lokal yang sudah tersedia. Daftar kosong berarti backend belum memberi bukti kandidat. Inventaris tidak menyertakan nama akun atau nomor seri perangkat.

Jalur tulis mendukung UEFI capsule perangkat dengan plugin `uefi_capsule` di fwupd 2.0.x. Aksi memakai ID perangkat dan versi yang dipilih, satu komponen, metadata LVFS stabil yang divalidasi fwupd, SHA-256 CAB, dan payload bertanda tangan. Mesin harus memakai daya AC yang terdeteksi. Jika kapasitas baterai tidak diketahui, UPower harus mengonfirmasi bahwa baterai tidak ada. Daemon harus memiliki `OnlyTrusted=true`. Cabang alternatif, downgrade, perangkat yang terkunci, emulasi, dan paket dengan hasil pencocokan ambigu ditolak.

Metadata dapat diminta melalui aksi refresh LVFS. Rencana memperlihatkan akses jaringan dan perubahan cache lokal. Remote unduhan aktif harus LVFS stabil dan URL metadata serta tanda tangan harus sesuai konfigurasi resmi. JSON mode fwupd melewati alur pelaporan otomatis pada perintah refresh. Pemeriksaan offline tidak mengunduh metadata ataupun firmware.

Saat fwupd 2.0.x belum melaporkan `ChecksumSig` sesudah refresh awal, whwmpc membaca hash JCat dari cache LVFS standar. Aplikasi mengikat path ke URI resmi, memeriksa kepemilikan root dan izin direktori, mencocokkan mtime metadata dengan daemon, serta memeriksa ukuran dan identitas file sebelum dan sesudah membaca. fwupd memvalidasi katalog. Pemeriksaan `trusted-metadata`, `OnlyTrusted`, dan checksum CAB tetap berlaku ketika menyusun dan menjalankan rencana. [Kode pembaruan metadata fwupd 2.0.20](https://github.com/fwupd/fwupd/blob/2.0.20/src/fu-engine.c#L4354) · [Hash cache fwupd](https://github.com/fwupd/fwupd/blob/2.0.20/libfwupd/fwupd-remote.c#L1044)

Setelah konfirmasi pembaruan, aplikasi mengunduh satu CAB melalui HTTPS, membatasi ukurannya, memeriksa SHA-256, dan meminta fwupd mencocokkan kembali GUID, versi, dan tanda tangan payload. Aplikasi memeriksa ulang perangkat, metadata, konfigurasi trust, dan daya setelah unduhan. Instalasi memakai otorisasi sistem melalui fwupd dan tidak melakukan restart otomatis. Simpan cadangan dan kunci pemulihan enkripsi saat meninjau rencana firmware.

Jika fwupd mencatat pending atau needs-reboot, restart sendiri sambil mempertahankan daya AC. Lanjutkan dari **Riwayat → Periksa firmware setelah restart**, dengan `whwmpc firmware --resume PLAN_ID`, atau dengan `whwmpc firmware --verify DEVICEID@VERSI` dari hasil aksi. Aplikasi menyimpan target handoff secara privat. Verifikasi mencocokkan versi rilis di `fwupdmgr get-history --json` dengan versi aktif yang dibaca ulang. Ketiadaan bukti yang cocok dilaporkan sebagai unknown. Backend ini tidak menyediakan pemulihan firmware.

Hasil verifikasi di TUI menampilkan kebutuhan restart, kegagalan, atau konfirmasi versi yang sudah terverifikasi. Versi aktif tampil bila fwupd berhasil membacanya. Piko merayakan hasil ketika riwayat dan versi aktif sudah cocok.

Fixture menguji pembacaan metadata, target berubah, digest unduhan, kecocokan CAB, izin, output rusak, metadata kedaluwarsa, dan pemisahan pending, gagal, serta hasil terverifikasi setelah reboot. Host pengembangan memiliki fwupd 2.0.20. Validasi host sebatas inventaris dan pembacaan konfigurasi. Flash dan reboot pada perangkat nyata memerlukan izin khusus.

Pada sandbox amd64, fwupd 2.0.20 memakai fixture ESRT upstream, HTTPS loopback, kunci PKCS#7 uji, ESP sementara, serta bus dan PolicyKit privat. CLI berjalan sebagai user biasa. Refresh bertanda tangan berstatus `verified` dari cache kosong. Konfirmasi salah dan perubahan AC berhenti sebelum unduhan CAB. Konfirmasi yang sah mengambil satu CAB, lalu daemon menulis capsule sintetis 4.112 B. `whwmpc firmware --resume` menunjukkan `reboot_required` pada 0.1.50. Sesudah simulasi boot, versi aktif 0.1.51 cocok dengan riwayat fwupd, capsule disingkirkan dari ESP, dan CLI mengembalikan `verified`. Uji pada LVFS publik serta flash dan reboot fisik memerlukan perangkat yang kompatibel dan persetujuan khusus.
